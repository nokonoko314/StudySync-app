# StudySync 詳細設計書

- 版: 1.0(2026-09-29)
- 前提: [01_要件定義書.md](01_要件定義書.md)、[02_ギャップ分析.md](02_ギャップ分析.md)
- 技術スタック: React 19 / TypeScript / Vite / Capacitor 8(Android) / Firebase(Auth・Firestore)

## 1. 全体構成

```
app/src
├─ state/        AppStateContext(データ本体・保存) / TimerContext(計測) / AuthContext
├─ lib/          日付・統計・同期・通知などの純粋関数
├─ components/   シート・カード・共通 UI
└─ screens/      Home / Calendar / Stats / Settings
```

- 画面は4タブ(ホーム・カレンダー・統計・設定)。教科は設定内、または ホームのメニューから開く。
- 状態管理は既存の Context + reducer を維持し、外部ライブラリは増やさない。

## 2. データモデル(`state/types.ts` の変更)

```ts
export type TaskStatus = 'pending' | 'tracking' | 'completed';

export interface Task {
  // 既存項目はすべて維持
  id: string; title: string; subjectId: string | null; projectId: string | null;
  dueAt: number | null; createdAt: number; order: number;
  isReview: boolean; reviewParentId: string | null; reviewStage: number;
  reviewEnabled: boolean; reviewIntervalsDays: number[] | null; generatedReviewTaskId: string | null;

  // 追加
  status: TaskStatus;                 // completed: boolean を置き換え
  completedAt: number | null;
  completedWithoutTracking: boolean;  // スワイプ等で計測せず完了
  scheduledStart: number | null;      // null = 未設定プール
  plannedMinutes: number;             // 既定 50
  carriedFrom: string | null;         // 繰り越し元の日付 yyyy-mm-dd
}
```

- `schemaVersion` を `AppData` に追加し、読み込み時に v1 → v2 へ変換する(`completed` → `status`、`scheduledStart = null`、`plannedMinutes = 50`)。
- `StudySession` はそのまま使う。計測開始でセッションを作り、停止で `endedAt` を確定する。

## 3. 主要なロジック(`lib/`)

| 関数 | 役割 |
|---|---|
| `layoutDay(tasks, day)` | その日の配置済みタスクを、重なりを考慮した列に割り当てる(クラスタごとに貪欲法で列を決定)。計測中のタスクは常に全幅 |
| `rubberBand(tasks, stopped, overrunMin)` | 計測停止時、予定の終わり以降にある未着手タスクを `overrunMin` だけ後ろへずらした新しい配列と、元に戻すための差分を返す |
| `carryOver(tasks, fromDay, toDay)` | 前日の未着手タスクを翌日の同じ時刻へ移す。元に戻す用の差分を返す |
| `dayRecords(data, day)` | その日のタスクと計測時間の一覧(カレンダー・プログラム詳細で共通利用) |
| `projectSummary(data, project)` | 期間・経過日数・合計時間・1日平均・教科別の内訳 |
| `minutesToLabel(min)` | 合計分を先に丸めてから時・分に分解する(「22:60」を防ぐ) |

すべて純粋関数にして、単体テスト(Vitest)を書く。

## 4. 画面・コンポーネント設計

### 4.1 ホーム
| コンポーネント | 責務 |
|---|---|
| `HomeHeader` | 相対見出し(今日の予定/昨日の記録/n日後の予定)、「今日」ボタン、メニュー |
| `WeekStrip` | 月〜日の7日、日ごとの合計時間。左右スワイプ(40px 以上、横方向優位)と ‹ › で週送り。`touch-action: pan-y` |
| `ProgramLanes` | 7列グリッドにプログラムの期間バー。重なりは段を分ける。タップで `ProgramDetailSheet` |
| `PoolRow` | 未設定タスクのチップ + 丸い「＋」。ドロップ先としてハイライト |
| `DayTimeline` | 時間目盛り、現在時刻線、ブロック、ゴースト、「現在時刻へ戻る」 |
| `TaskBlock` | ドラッグ移動・下端で伸縮・横スワイプ・計測ボタン・編集ボタン |
| `UndoToast` | 画面共通。5秒で自動的に閉じる。`aria-live="polite"` |

### 4.2 ドラッグの共通仕様(`useDrag` フック)
1. `pointerdown` で開始し、`pointerId` を記録する。以後、別の指のイベントは無視する。
2. 6px 動くまでは方向を決めない。縦方向ならタスクの移動、横方向ならスワイプとして扱う。
3. `pointerup` で確定する。`pointercancel` のときは元の位置・長さに戻す。
4. どの場合も、登録したイベントリスナーは必ず解除する。

### 4.3 シート
- 共通の `BottomSheet` 部品を使う(背景タップ・Esc・Android の戻るボタンで閉じる。入力内容が変わっていれば破棄の確認を出す)。
- `TaskSheet`(作成と編集を兼ねる)、`ProgramDetailSheet`、`DayDetailPanel`(カレンダーの下部にも、プログラム詳細の中にも使う)。

## 5. 永続化と同期

| 層 | 方式 |
|---|---|
| 端末内 | 現行どおり localStorage(`AppData` 全体を JSON で保存)。書き込みは 300ms にまとめる |
| クラウド | `cloudSync.ts` で Firestore の `users/{uid}/data` に保存。項目ごとに `updatedAt` を持たせ、新しい方を採用する |
| ルール | `request.auth.uid == uid` のときだけ読み書きを許可する |

## 6. 通知

- 予定開始の5分前(設定で変更可)に `@capacitor/local-notifications` で通知する。
- タスクの配置・移動・削除のたびに、その日と翌日の通知を予約し直す。

## 6.1 Google 連携・Google カレンダー同期

| 項目 | 方式 |
|---|---|
| ログイン | `@capacitor-firebase/authentication` の Google ログイン(`app/` に導入済み)。Web 版は Firebase Auth の `signInWithPopup` |
| 権限(スコープ) | `openid email profile` は必須。カレンダーは利用者が選んだときだけ追加で要求する: 読み込み `calendar.readonly`、書き出し `calendar.events` |
| 予定の取得 | Google Calendar API `events.list`(`timeMin`〜`timeMax` は表示中の週 ±1週、`singleEvents=true`)。`syncToken` で差分だけ取得する |
| 書き出し | 初回に「StudySync」カレンダーを `calendars.insert` で作り、配置済みタスクを `events.insert/patch/delete` で反映する。イベントの `extendedProperties.private.studysyncTaskId` でタスクと対応づける |
| 同期のタイミング | アプリを開いたとき・15分ごと(アプリ起動中のみ)・手動の3択 |
| 表示 | ホームのタイムラインには枠線だけの「外部予定」として表示し、ドラッグはできない。カレンダーではカレンダーごとに表示・非表示を切り替える |
| 事前準備 | Google Cloud でプロジェクトを作り、Calendar API を有効化し、OAuth 同意画面を設定して Android(パッケージ名と SHA-1)と Web のクライアント ID を作成する。カレンダーの権限は「機密性の高いスコープ」のため、一般公開前に Google の審査が必要 |

## 7. テスト計画

| 種類 | 対象 | 方法 |
|---|---|---|
| 単体テスト | `lib/` の純粋関数(重なりの配置、ラバーバンド、繰り越し、時刻表示) | Vitest |
| 結合テスト | ドラッグ・スワイプ・元に戻す・シートの破棄確認 | Testing Library + ポインターイベントの合成(pointercancel を含む) |
| システムテスト | 画面遷移、同期、通知、日付をまたぐ動作 | Android エミュレーター(Pixel 8a) |
| 受入テスト | 実際の勉強で1週間使う | 実機(スマホ + タブレット) |

## 8. 配布

- 確認用: `preview-app/`(モックアップをそのまま全画面化したプレビュー版。applicationId `com.studysync.preview`)
- 正式版: `app/`(applicationId `com.studysync.app`)。移植が済んだら署名済みの AAB を作り、Google Play の内部テストで配布する。
