# StudySync ギャップ分析

- 版: 1.0(2026-09-29)
- 比較対象: 要件([01_要件定義書.md](01_要件定義書.md)) ⇔ 現行アプリ `app/`(React 19 + Capacitor 8 + Firebase)

## 1. 結論

現行アプリはタスクを**締め切り(dueAt)ベースのリスト**で管理しており、モックアップの中心である**「時間軸上に開始時刻と長さを持つ予定」**という概念がありません。そのため、ホーム画面はほぼ作り直し、データモデルには予定の項目を追加する必要があります。一方で、計測記録(StudySession)、教科、プログラム(GroupProject)、Firebase 同期、通知、復習の自動作成は流用できます。

## 2. 機能ごとの差分

判定: ◎ 流用可 / ○ 改修 / △ 大幅改修 / × 新規

| 要件 | 現行アプリ | 判定 | 必要な対応 |
|---|---|---|---|
| F-H01〜02 時間軸と現在時刻の追従 | `TimelineScreen` は計測結果を見るだけ。1/3固定の追従なし | △ | ホームにタイムラインを統合し、追従ロジックを移植 |
| F-H03〜05 ドラッグで配置・移動・伸縮・未設定へ戻す | 並び替え(`DraggableTaskGroup`)のみ | × | ポインターイベントでドラッグを新規実装(pointercancel 対応込み) |
| F-H06〜07 計測・ゴースト・ラバーバンド | `TimerContext` で計測可。予定との関係なし | ○ | 計測をタスクの予定枠と結び付け、超過時の後ろずらしを追加 |
| F-H08〜10 スワイプ・元に戻す・未完了に戻す | 完了の切り替えはあり。元に戻す通知なし | ○ | 共通の Undo トーストを作る |
| F-H11〜12 週のスワイプ・今日ボタン | なし | × | 週ストリップ部品を新規作成 |
| F-H13〜14 プログラムの期間バー → 詳細 | `ProjectDrawer` / `ProjectDetailSheet` あり | ○ | 期間バーを追加し、詳細シートにカレンダーと統計を追加 |
| F-H15 開始前の通知 | `notifications.ts` は締め切り前の通知 | ○ | 予定開始の N 分前の通知を追加 |
| F-H16 前日分の繰り越し | なし | × | 日付が変わったときの処理を追加 |
| F-T01〜08 作成・編集シート | `AddTaskSheet` / `TaskDetailSheet` あり | ○ | 1画面1主操作、破棄確認、IME 対策、時刻・所要時間の入力に揃える |
| F-C01〜04 カレンダーと日別詳細 | `CalendarScreen` あり(タップで遷移) | ○ | タップで下部に詳細を出す形に変更 |
| F-P01〜04 プログラム詳細 | 基本情報のみ | ○ | 期間カレンダー・統計・教科別の内訳を追加 |
| F-S01〜04 統計・教科・設定・復習 | あり | ◎ | 見た目をデザイントークンに合わせるのみ |
| N-03〜04 オフライン・同期 | localStorage + `cloudSync.ts` | ◎ | 新しい項目を同期対象に追加 |
| N-07 ドラッグ中断時の復元 | 該当なし | × | 全ドラッグ部品で共通化 |
| N-08 デザイントークン | `theme.css` あり(配色が異なる) | ○ | スレート×シルバー/水色のトークンへ置き換え |

## 3. データモデルの差分

| 項目 | 現行 | 必要 |
|---|---|---|
| 予定開始時刻 | なし(`dueAt` は締め切り) | `scheduledStart: number \| null`(epoch ms、null = 未設定) |
| 予定の長さ | なし | `plannedMinutes: number` |
| 状態 | `completed: boolean` | `status: 'pending' \| 'tracking' \| 'completed'` と `completedWithoutTracking: boolean` |
| 繰り越し | なし | `carriedFrom: string \| null`(yyyy-mm-dd) |
| 計測との関連 | `StudySession.taskId` | そのまま流用(1タスクに複数セッション可) |
| プログラム | `GroupProject`(startDate/endDate あり) | そのまま流用。`Task.projectId` で紐付け |

## 4. 移行時の注意点

1. 既存ユーザーのデータ: `completed` から `status` への変換と、`scheduledStart=null`(未設定扱い)での移行処理が必要です。
2. 「締め切り」の扱い: 現行の締め切りと復習機能は残します。締め切りのあるタスクは、未設定の一覧で締め切りが近い順に並べます。
3. ナビゲーション: 現行の `navOrder` にある `timeline` はホームに統合するので削除します(設定値の移行も必要です)。

## 5. 作業量の見積もり(目安)

| フェーズ | 内容 | 目安 |
|---|---|---|
| 1 | デザイントークンの差し替え、データモデルの拡張と移行 | 1〜2日 |
| 2 | ホームのタイムライン(配置・移動・伸縮・計測・ラバーバンド・元に戻す) | 3〜5日 |
| 3 | 作成・編集シート、週ストリップ、プログラムの期間バー | 2日 |
| 4 | カレンダーの日別詳細、プログラム詳細 | 2日 |
| 5 | 通知・繰り越し・同期の追加、実機テスト | 2〜3日 |
